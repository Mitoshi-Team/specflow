## Why

Замечание ревью хакатона: часть клиентской логики полагается только на локальное хранилище браузера без серверной персистентности, а ошибки записи батчей подавляются молча. Результаты пакетной обработки теряются при очистке кэша, в другом браузере или инкогнито-режиме, и не хранятся на сервере — при рестарте сервиса история недоступна.

## What Changes

- **Серверная история батчей**: `POST /api/v1/extract/batch` сохраняет выполненный батч (счётчики, порог, исходные карточки, полный ответ) в PostgreSQL (сервис `postgres` в docker-compose) и всегда возвращает `batch_id`
- **Признак `persisted`**: при сбое записи ответ содержит `persisted=false` — клиент предупреждает о риске потери, причина фиксируется в логе с traceback (ошибка не подавляется)
- **Новые эндпоинты**: `GET /api/v1/batches` (история с пагинацией, новые первыми) и `GET /api/v1/batches/{batch_id}` (полный батч); недоступность хранилища → 503 ErrorResponse, 404 для неизвестного id
- **Режимы хранения**: `EXTRACTOR_DATABASE_URL` задан → PostgreSQL; не задан → хранилище в памяти процесса (dev без БД), выбор режима логируется при старте
- **Frontend**: страница результатов показывает панель «Предыдущие батчи» с сервера, загружает батч по `?batch_id=`, локальное хранилище остаётся фолбэком; запись в localStorage больше не подавляется молча (булев результат с последствием для навигации)

## Impact

- `services/contracts` — модели `BatchSummary`, `BatchListResponse`, `StoredBatchResponse`, поле `persisted` в `BatchExtractResponse`
- `services/attribute_extractor` — модуль `batch_store.py`, эндпоинты истории, зависимость `psycopg`, переменная `EXTRACTOR_DATABASE_URL`
- `docker-compose.yml`, `.env.example` — сервис `postgres` и учётные данные для локальной разработки
- `services/frontend` — панель истории, загрузка батча по id, i18n-ключи, предупреждения о несохранённых результатах
- `openspec/specs/api_contract.md`, `openspec/specs/frontend.md` — новые эндпоинты и семантика персистентности
- README (корневой, сервисов) — документация эндпоинтов и настройки PostgreSQL
