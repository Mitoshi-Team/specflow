# API Gateway

Публичный HTTP-API SpecFlow на FastAPI.

## Устройство

- `src/api_gateway/main.py` — фабрика приложения `create_app()` и объект `app`.
- `src/api_gateway/proxy.py` — тонкий прокси публичных маршрутов в сервис
  извлечения атрибутов (логики извлечения в шлюзе нет).
- `src/api_gateway/config.py` — настройки Pydantic (`API_GATEWAY_*`): версии,
  порог уверенности, лимиты батча и таймауты upstream с валидацией.
- `src/api_gateway/constants.py` — значения по умолчанию (маршруты, CORS,
  версии, пороги, лимиты, таймауты).
- `tests/` — unit-тесты.

## Запуск

Из корня репозитория:

```bash
uv run uvicorn api_gateway.main:app --reload
```

## Роль шлюза

Шлюз не содержит логики извлечения: всё, что приходит под `/api/v1/*`
(кроме локального `/api/v1/health`), он передаёт «как есть» в сервис
извлечения атрибутов по адресу `API_GATEWAY_ATTRIBUTE_EXTRACTOR_URL` и
возвращает его ответ без изменений. Так публичный контракт обслуживается с
одного origin. Если upstream недоступен, шлюз отвечает `502` с
`ErrorResponse` (`code: "http_error"`).

| POST | `/api/v1/extract/batch` | Проксируется в сервис извлечения |
| GET | `/api/v1/batches` | Проксируется в сервис извлечения (история батчей) |
| GET | `/api/v1/batches/{batch_id}` | Проксируется в сервис извлечения (сохранённый батч) |
| GET | `/api/v1/categories` | Проксируется в сервис извлечения |
| GET | `/api/v1/categories/{category}` | Проксируется в сервис извлечения |
| GET | `/api/v1/info` | Проксируется в сервис извлечения |
| GET | `/api/v1/config` | Проксируется в сервис извлечения |
