# colab_ner

Готовая папка для обучения NER-модели в Google Colab — всё в одном месте,
без лишних файлов проекта.

## Содержимое

- `ner_training_colab.ipynb` — блокнот обучения (ruBERT-base, weak-разметка → BIO).
- `data/train.jsonl`, `data/val.jsonl` — weak-датасет (в git не хранится,
  см. `.gitignore`; копируется из `data/ner/`).

## Запуск

1. Загрузи всю папку `colab_ner` в Colab (или один zip с ней).
2. Открой `ner_training_colab.ipynb`.
3. `Среда выполнения → Сменить тип среды выполнения → T4 GPU`.
4. `Ctrl+F9` (запустить всё). Блокнот сам найдёт файлы данных рядом с собой;
   если не найдёт — покажет диалог загрузки `train.jsonl`/`val.jsonl`.

## Долгий прогон

По умолчанию блокнот учит 6 эпох при `lr=2e-5` — на T4 это примерно час.
Прогон рассчитан на «оставить и уйти»:

- чекпойнты пишутся локально в `/content/ner_model` каждые `SAVE_STEPS` шагов
  (хранятся последние 3); на Drive чекпойнты не пишутся — квота;
- при `RESUME=True` повторный запуск ячейки обучения продолжает с последнего
  чекпойнта, а не начинает заново;
- на Drive в конце пишется только чистый архив модели (~0.7 ГБ) с версией в
  имени (`ner_model_v3.zip` — константа `MODEL_VERSION` в блоке параметров;
  инкрементируй её при каждом переобучении, версии не перезаписывают друг
  друга). Удалённое в Drive попадает в Корзину и продолжает занимать квоту —
  освобождается только после «Очистить корзину».

«Прилипшая» среда без CUDA: «Отключиться и удалить среду» → заново T4.

## Результат

По окончании получится `ner_model_<версия>.zip` (в Drive или браузером).
Распакуй в каталог модели (`models/ner_v3` и т.п. по версии) — внутри
структура без изменений: `TransformersSpanPredictor` загружает её указанием
пути без конвертации.

Метрики в блокноте считаются по сущностям со сноской special/padding-позиций: в
`compute_metrics` предсказания на позициях с истинной меткой `-100`
маскируются — иначе argmax на них даёт тысячи ложных сущностей и занижает
precision (на реальном прогоне: 0.35 → 0.955 OVERALL после фикса).
